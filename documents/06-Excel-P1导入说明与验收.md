# Excel 严格 P1 导入

日期：2026-10-17；对应 PRD v0.3 / FR-12。

## 操作步骤

1. 打开本地应用，点击右上角“导入 Excel”。若仍是旧版本，停止旧服务并执行 `npm run dev`，然后刷新。
2. 选择本机文件 `resources/bringing_up_bebe_vocabulary_strict_P1_P2_P3.xlsx`。
3. 确认预览显示章节明细 1,098 行，P1/P2/P3 为 120/514/464；仅 P1 可入库，其他 978 行及三张汇总表排除。
4. 选择复用已有 Reading 来源，或新建 `Bringing Up Bébé`。来源默认标为读完，不伪造作者、阅读日期等未提供信息。
5. 展开分组检查。可勾“仅查看已有同词 / 等级冲突”快速定位；已有同词默认跳过，需明确选择新建、每行独立保存或追加已有 P1。已有低等级不能直接追加，不自动升级。
6. 勾选批量确认，点击“确认导入 N 条 P1”；成功后点击“查看本书的表达”，默认筛选 P1。需要临时排除某组时选“本组暂不导入”。

空库、默认组内合并时为 **112 个表达、120 条 P1 语境**。112 按实际词条与相同中文义项分组，与原表 101 个去重复习目标口径不同。已有数据、跳过分组或选择拆分都会改变结果，以确认前后页面显示为准。

## 数据保留与确认边界

- 只读取带有章节明细列名的工作表，忽略统计和两张 P1 汇总表；按严格等级 J 列过滤，而非旧等级。
- Expression 保留原词条及词典中文义项；Context 单独保留英文语境解释，不把词典中文当成已核实的语境翻译。
- 原句、章节、原有页码、文件名/工作表/Excel 行号、音标/词性、词典解释、复习目标、原等级、严格理由、归一词条和原表次数保留。
- 不用训练搭配替换原词条，不填补缺失页码，不还原被省略的原文。Why Saved 默认 useful，详情明确标为“导入默认”。
- 每行明细是一次 exposure；Used=0，不按表内次数复制事件。全部解析在本机进行，无 AI、OCR 或外部内容上传。
- 预览不写业务库。用户确认后直接批量入库，是已整理 Excel 的特例；手动采集仍走 Inbox。原始 Excel 不被改写或保存副本，`resources/*.xlsx` 不加入 Git。

## 实现与恢复行为

新增 `/api/imports/preview` 和 `/api/imports/commit`；两者仍需本机 Host 和同源 Origin。上传 JSON 上限 8 MB、Excel 上限 5 MB、解压上限 40 MB、章节明细上限 5,000 行；拒绝旧格式、加密或损坏文件、无效列名及所用单元格公式。读取前校验压缩目录及逐条实际解压大小，防止仅信任声明大小。

预览中的 P1 行由本机服务签名，有效 30 分钟；客户端不能修改后绕过等级过滤。密钥只在进程内，服务重启后需重新上传。此签名不代表释义或原文已被外部核实。

批次外层事务与单条保存的 savepoint 保证整批原子性，无表结构迁移。任何一条失败均回滚来源、表达、Context 与保存草稿；不影响既有数据。失败可保留预览重试；已导入到同一来源的同一原明细会跳过，包括改文件名重传。首次成功响应丢失时，仅在所有选中行都已存在于唯一同名来源的情况下安全返回重放结果。

重复判定按章节、原表行号、实际词条、原句和页码；改动这些内容属于新导入证据，需要重新检查，不承诺识别任意重排/编辑后的同一表格。暂未提供整批撤销；确认前应检查来源、分组及条数。

ExcelJS 在服务端通过 Node 加载，避免把解析器打入客户端或保留旧的依赖打包路径。为移除旧 uuid 审计项，将 ExcelJS 间接依赖约束到兼容的 uuid 11 修复版本；运行时 `npm audit --omit=dev` 复查为 0 项。具体版本以 package-lock.json 为准。
