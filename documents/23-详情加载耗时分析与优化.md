# 详情加载耗时分析与优化

日期：2026-10-18。用户反馈：iPhone 不开代理时词条详情需数秒，开代理明显更快。当前正式环境和数据见 [22](22-正式登录验收与学习库迁移.md)。

## 1. 实测与结论边界

- 服务器负载约 0.06/0.05/0.07，1.9Gi 内存约 1.3Gi 可用，无交换占用；app CPU 接近 0%、内存约 83Mi。当前证据不支持因 CPU/内存不足而先升级规格。
- 从 Mac 对公网健康接口进行三次新连接采样，直连总耗时 1.00/0.88/2.05 秒；本机代理 0.63/0.64/0.70 秒。各次均 HTTP 200，未绕过 TLS。直连 TLS 完成约 0.42–1.38 秒，代理约 0.43–0.45 秒。说明链路差异和抖动存在；三次样本不是 SLA，也不等于 iPhone/办公网的实际点击耗时。
- 服务器到 Supabase settings 的首次连接约 375ms，后续 82/68/58ms。此接口不需要用户登录；只能证明基本认证服务连通成本，不能将其当作 getUser 鉴权或真实词条接口耗时。
- 代码确认：每次导航先等待 sources + drafts，再开始 expressions/:id；因此首屏正文存在两轮串行网络/鉴权等待。Review 资格另有后续请求，但原本不阻塞正文，不在本轮改动范围。

## 2. 修改合同

词条详情请求与辅助来源/Inbox 请求同轮立即发出；正文只等待自身响应。来源/Inbox 继续真实刷新，不新增持久缓存，不缓存鉴权，不略过所有者检查，不公开业务数据。

编辑维护需要来源信息，辅助数据成功返回前不挂载维护表单；失败保留已读详情、显示重试提示，重试后恢复编辑。来源标题、语境和统计直接来自详情响应，不依赖辅助列表填充。草稿页同时发起草稿和辅助读取，仍等来源准备完成再开放编辑。保留导航清理 active 标记和原有写入版本/generation 防护，过时响应不覆盖当前页面。

不承诺优化后大陆直连与代理一样快；它去掉客户端串行等待，不修复运营商路由、跨境丢包或 DNS/TLS 握手耗时。没有为性能降低登录校验、关闭 TLS、配置公有 API/CDN 缓存或迁移数据库。

## 3. 验证与部署合同

1. 浏览器测试把来源/Inbox 响应一直阻塞，必须在释放前看到详情正文；编辑按钮仍不可用。释放辅助请求后才能编辑。这是依赖关系测试，不用任意毫秒阈值冒充公网性能验收。
2. 辅助请求失败时详情仍显示，维护入口不可用，解除故障并重试后恢复。回归原有采集/保存、维护/恢复、两种 Excel 导入及 Review。
3. 服务器先构建独立镜像，不打断运行服务；所有测试通过后，短暂维护、生成一致性快照/业务清单、替换 app 镜像，核对前后清单和 HTTPS/保护，再解除维护。备份服务和数据卷不更换，保留旧镜像及配置用于回退。
4. 由用户刷新手机页面后比较无代理的实际体验。服务器构建/测试通过不等于手机实网体验验收。
