# ReadWords 本地备份恢复与数据维护

日期：2026-10-17。需求依据：PRD v0.4 的 FR-04、FR-09；当前数据库 schema 为 2。此增量不部署云端，不接入 AI/Review，也不宣称完整 R0/C0 验收。

## 1. 从哪里操作

| 目的 | 操作路径 |
|---|---|
| 下载全部数据 | 左下“本地工作空间”→“备份与恢复”→“下载全库 JSON 备份” |
| 恢复文件 | 同页面选择 JSON → 检查数量及恢复前快照 → 勾选整库替换确认 → 确认替换 |
| 撤回一次恢复 | 设置中下载对应“恢复前快照”→ 作为 JSON 再预览恢复 |
| 修改正式表达 | Library 来源下或 Search → 打开表达 →“维护已保存数据”→“编辑表达” |
| 修改原句/事件等 | 同区域对应记录“编辑语境 / 归属”→ 修改 → 保存 |
| 修正误匹配 | 编辑语境时选择另一条表达/义项或来源；只移动当前语境，不合并整条表达 |
| 表达归档/恢复 | 详情归档；Search 勾“包含归档表达”后可查阅并取消归档 |
| 删除与恢复语境 | 详情删除语境；在同一表达“语境回收站”恢复 |
| 删除与恢复表达 | 详情移入回收站；设置“表达回收站”恢复 |

Library 展示已经确认入库的内容及其来源，Inbox 是待整理草稿。Excel P1 预览确认后直接入正式库。两者都持久化，但正式库编辑不会反向重写当时的采集草稿。

## 2. 备份格式与替换规则

- 格式：`format=readwords-backup`、`schema_version=2`、`exported_at`，以及 sources、expressions、contexts、drafts 四个数组。data 是结构化对象，不是嵌套 JSON 字符串。
- 包含稳定 ID、业务字段、原始导入元数据、归档/删除状态、草稿入库结果关联、创建/更新时间及版本；计数由有效语境派生，不导出缓存计数。
- 没有 Review/AI 实体的当前版本不伪造这些记录。将来新增实体必须扩展备份 schema 与迁移，未知版本明确拒绝。
- 不导出运行态库 generation、预览令牌、密钥、日志或缓存。JSON 可能含私人原句和写作，下载前界面有说明。
- 当前接受不超过 50 MiB（界面简称 MB）的 UTF-8 JSON，仅接受当前 schema 2，不支持合并、其他软件 JSON 或原始 SQLite 文件上传。当前库超出此恢复上限时，拒绝生成无法按本流程恢复的导出或预览，需保留数据库并另行升级容量方案。
- 导出和恢复前快照均在一致性事务内读取。逐项校验 ID 唯一、字段枚举/长度、时间格式/顺序、引用、规范表达、事件指纹、级联删除标记和草稿结果；合法软删除引用仍保留。
- 每份数据库使用独立的 snapshots/<数据库文件名>/ 目录，避免切换数据库时混入另一库快照。恢复预览不修改学习记录；先写入并 fsync 当前库 JSON 快照，再展示双方数量。快照文件权限 0600，目录创建权限 0700；未完成快照时不开放确认。
- 预览令牌在本服务进程内保存，10 分钟有效，最多同时保留 3 份；重启/代码热更新或更多预览可能使旧令牌失效。只接受本次预览对应的库和内容，期间库有变化即拒绝替换并要求重新预览。
- 恢复明确确认后，在同一 SQLite 事务中替换全部业务记录并检查外键；中途失败整体回滚，原库和 generation 保持原值。成功后更新 generation、使令牌失效并重新载入页面。
- 所有业务写入带当前库 generation，旧页面、旧导入预览和响应丢失后的旧请求不能在恢复后的库继续写入。其他窗口出现提示时先复制未保存输入，再刷新；不自动合并旧输入。

自动快照与主库在同一 Mac，不能应对整机/磁盘丢失；请把下载的 JSON 另存到安全位置。未实现定时备份、自动快照清理或云端备份。

## 3. 编辑、状态与计数

表达可改 term、义项释义、类型、P1/P2/P3、简单替换。改名更新 normalized_term，但允许同形多义，不自动合并；原句和每条语境释义不随表达编辑覆写。

语境可改原句、释义、实际出现形式、来源、表达归属、事件、章节/页码/听力位置、接触日期、原因、备注、误听及写作前后内容。按来源校验事件：阅读/听力只允许 exposure，纠正限 Writing 且必须有不同原表达与目标表达；other 原因需备注。源自 Excel 的原始元数据保留用于追溯，不冒充当前编辑结果。已归档来源的现有语境仍可维护，改到其他归档来源前须先恢复该来源。

草稿、来源、表达和语境使用版本检查；旧版本返回 409，输入不清空。改语境归属与计数更新在同一事务中完成；目标须为未删除表达，可能重复的有效事件须额外确认。改归属保留历史已保存草稿的原入库结果，不使旧草稿重新提交成新事件。

Seen 只计有效 exposure，Used 只计有效 output_used；纠正不增加 Used。来源卡片只统计有效语境关联的未删除表达。删除最后一条语境不删除表达，显示“无上下文”。

表达归档不删语境；表达删除将当时有效语境标记为本次级联删除。恢复表达恢复原 active/archived 状态，并仅恢复本次级联的语境；此前单独删除的记录仍在语境回收站。没有永久清空、来源删除、批量合并/拆分或整批撤销导入。

## 4. 数据库升级与人工应急

旧 schema v1 打开时，先使用 SQLite `VACUUM INTO` 生成自包含的一致性 `before-schema-v2-<UUID>.sqlite` 文件，再在事务内升级到 v2。升级新增 Context 的 lifecycle/version/updated_at/deleted_by、Expression 的 restore_lifecycle，以及保存库 generation 的 workspace_meta 系统表；原有业务 ID 和字段保留。快照或迁移失败则不进入新版本服务；更高未知 schema 拒绝打开。

默认主库为项目 `data/readwords.sqlite`，快照目录 `data/snapshots/readwords.sqlite/`。设置过 READWORDS_DB_PATH 时，快照位于该数据库父目录的 snapshots/<数据库文件名>/ 中。仅运行一个使用该库的服务；不要在运行中替换主 sqlite 或删除 WAL/SHM。

升级前 SQLite 快照不是 JSON，只用于人工应急：

1. 停止所有使用当前库的服务；复制并保留当前完整数据目录，以免丢失升级后新增记录。
2. 新建一个空恢复目录，例如项目 `data/recovery-20261017-1/`；把选定的 `before-schema-v2-*.sqlite` 复制进去，命名为 `readwords.sqlite`。不要覆盖现有数据库，也不要把运行中主库的 WAL/SHM 混进这个目录。
3. 用 READWORDS_DB_PATH 指向该复制文件启动当前程序。程序会先另做快照，再把复制件从 v1 升级为 v2；原目录保留。示例：`READWORDS_DB_PATH="$PWD/data/recovery-20261017-1/readwords.sqlite" npm run dev`。
4. 核对来源、表达、语境、日期与数量后再决定后续切换。此路径恢复到旧快照时间点，不会自动包含之后的新数据，不做两份库的自动合并。

日常误操作优先使用设置里的 JSON 快照恢复；物理磁盘损坏、断电和整机灾难恢复尚未验收。

## 5. 技术接口与客户端边界

全部业务写入继续校验本机 Host、Origin、JSON Content-Type 和库 generation。获取 `GET /api/backup/status` 或业务 GET 响应头可取得 generation；API 客户端自动附加 `X-ReadWords-Generation`。首次升级后旧版页面需刷新。

| 接口 | 行为 |
|---|---|
| POST /api/backup/export | 一致性全库 JSON |
| POST /api/backup/preview | 流式限额 50 MiB，校验、快照及预览 |
| POST /api/backup/restore | token + confirmed=true，事务整库替换 |
| GET /api/backup/status | schema、generation、快照目录与清单 |
| POST /api/backup/snapshot | 下载已登记文件名对应的 JSON 快照，拒绝路径穿越 |
| PATCH /api/expressions/:id | data + version + 可选 active/archived |
| POST /api/expressions/:id/delete 或 restore | version，软删除/恢复 |
| PATCH /api/contexts/:id | data + version + expressionId + 可选 allowDuplicate |
| POST /api/contexts/:id/delete 或 restore | version，单条语境删除/恢复 |
| GET /api/trash | 被删除表达清单；单独删除的语境在原表达详情恢复 |

Excel 请求仍限制 8 MiB、普通写入 128 KiB。恢复预览单独提高到 50 MiB，未放宽其他端点。生产构建在独立 .next-verify 目录验证；浏览器测试使用 3100 端口和临时 SQLite，避免对实际学习库执行恢复或编辑。

- 已只读检查当前 3000 服务：新版备份状态接口返回 schema 2；现有库与升级前 SQLite 快照的四类业务记录 ID 集合一致，未执行用户库业务编辑或恢复。升级前快照保留在最终分库目录中。
- `npm run typecheck`、`npm run format:check`、`npm run guide:check`、独立生产构建与文档链接检查均通过；Markdown 链接、表格列数及 F/CF/CA 编号已核对。

Safari、VoiceOver、大容量、物理磁盘写满/断电、云端部署及完整 R0/C0 验收不在本轮通过结论内。失败注入验证事务行为，不等于物理硬件故障测试。自动化测试不对用户学习库进行编辑、删除或整库恢复；运行新版应用时仅有必要的带快照 schema 升级。


验收时修正的事项：恢复前快照按数据库文件名隔离，防止共用目录时混入另一库；确认替换前再次校验快照仍完整；本轮曾并行运行生产构建和开发服务测试，构建触发的类型文件更新干扰了开发服务页面刷新，改为构建后单独完整回归并通过。原自动化流程没有跳过或删除失败断言。
