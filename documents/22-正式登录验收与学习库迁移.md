依赖：[15 操作手册](15-邮箱登录配置与部署操作手册.md)、[18 备份手册](18-COS异地备份与恢复实施手册.md)、[21 重启验收](21-服务器重启与持久化验收.md)。本轮先完成操作合同和回退准备，再逐项记录真实结果，不能将待用户查收邮件/输入密码的步骤标为通过。

## 1. 第 4 步：认证验收合同

- 应用正式 origin 固定 https://phrasebud.com，唯一所有者 UUID、已验证邮箱、HTTPS Secure Cookie 和 API 鉴权保持。
- Supabase Site URL 为 https://phrasebud.com；Redirect URLs 包含精确的 https://phrasebud.com/reset-password，不用任意域名通配。
- Reset Password 邮件模板使用本应用支持的入口：`https://phrasebud.com/auth/confirm?token_hash={{ .TokenHash }}&type=recovery`（HTML 属性中 & 写为 &amp;）。默认 ConfirmationURL 模板不能直接当作应用自定义 token_hash 回调验收通过。
- 自定义 SMTP 负责正式邮件送达；Supabase 默认发送器仅适合限制范围内的测试，不承诺生产送达。恢复发送接口统一返回成功文案，不证明邮件真正发送。
- 用户自己完成忘记密码、真实邮件、设置新密码、重新登录；不向聊天提供密码/邮件恢复 token。已验证的旧密码登录可以继续使用，邮件恢复缺口要如实记录，不降低权限校验来绕过。

官方依据：[Redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls)、[邮件模板](https://supabase.com/docs/guides/auth/auth-email-templates)、[自定义 SMTP](https://supabase.com/docs/guides/auth/auth-smtp)。

## 6. 日常使用和运维入口

日常所有设备均访问 [https://phrasebud.com](https://phrasebud.com)，使用原邮箱密码；后续修改密码后使用新密码。无需启动 Mac 的 localhost 或 Docker Desktop，云端数据和日备份由服务器持久卷承载。办公电脑使用完退出账号，不保存共享设备上的密码。

Mac 的 `data/readwords.sqlite` 保持维护只读，作为切换时的回退副本；不要自行解除维护后两边同时写。现有 localhost:3001 是独立认证测试库，也不是正式数据。正式环境开始写入后，不能拿旧 Mac 库直接覆盖它。

在服务器查看正式环境：

```bash
cd /home/ubuntu/readwords
docker compose --env-file .env.production -f source/deploy/compose.yaml -f source/deploy/compose.production-volumes.yaml config --quiet
docker compose --env-file .env.production -f source/deploy/compose.yaml -f source/deploy/compose.production-volumes.yaml ps
docker compose --env-file .env.production -f source/deploy/compose.yaml -f source/deploy/compose.production-volumes.yaml logs --tail 20 backup
```

不运行会公开打印认证配置的完整 config/inspect env。正常重启/更新沿用这两个 -f 参数和 .env.production，保留 external 数据/证书卷；不启动旧 preview 代理或备份。旧预演数据与证书卷虽然名称带 preview，但现有 TLS 卷现由正式代理独占使用，不能当作测试垃圾删除。

查看当前正式备份（服务休眠时可只读查看快照；手工作业须避免与日调度并发）：

```bash
docker compose --env-file .env.production -f source/deploy/compose.yaml -f source/deploy/compose.production-volumes.yaml run --rm --no-deps --entrypoint restic backup -o s3.bucket-lookup=dns snapshots
```

恢复须先暂停日调度并确认无活动作业，创建空的隔离恢复目录，挂载至 /restore，再 restic restore 当前快照 --target /restore。当前备份产生于冻结期间，恢复副本可能仍为维护只读，核对后由运维明确解除。原生恢复库需要可写的隔离目录来创建 SQLite WAL/SHM；若冻结源以只读挂载导致校验失败，使用事先验证的 manifest JSON 比较，不复制或删除运行源库的侧文件。

正式卷部署后尚未再次做宿主机重启；21 的实际宿主重启证据适用于之前 preview，不能冒称已对新正式卷做同轮重启。当前数据已安装到持久卷并通过新正式容器启动前后校验；未来重启仍需按 21 冻结、备份和比较流程处理。
