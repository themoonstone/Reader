## 1. 实施范围与逻辑自检

| 步骤 | 交付及检查 |
|---|---|
| D1 数据保护 | schema 2→3 前 `VACUUM INTO` 一致性快照（文件及目录 fsync），随后事务建表；新库默认池为空。新增四业务表和一运行租约表。原业务表保留 ID、字段与导入元数据 |
| D2 手动池 | P1/P2 与材料资格、20 活跃义项、批量全成全败、版本及旧操作重放保护；暂停/移出保留收藏、首次引入与历史。维护事务提交前自动暂停/失效，恢复实体不自动恢复池 |
| D3 认义 | 真实已存原句/正确改句，独立目标表达；题面 API 没有答案字段，练习期间不渲染候选/池里的释义。揭晓后分开显示义项与语境释义；Farm K 只作答案后的学习改写 |
| D4 会话 | 本轮时间/卡数/首次引入与全日本地日期配额；旧表达按上次展示轮换；同会话每义项一次；发卡/反馈幂等；最后一张可反馈，时间到先拒绝反馈并允许只读揭晓 |
| D4 持久化 | 5 秒前台心跳、15 秒写租约、请求串行、可控时钟、明确继续；长间隔以最近成功点暂停。反馈插入、间隔更新、卡状态、计时同事务；失败无半记录 |
| D5 页面 | Review 设置/池候选分页及来源筛选、详情入池、开始/揭晓/反馈/跳过/暂停/继续/结束、无候选空态、具体冲突提示。保留原导航和导入/采集入口 |
| D6 文档 | 更新使用指南同源文件及生成稿、PRD/Feature List/11/12/备份说明；测试与未验收分开记录。D6 保持未关闭，D7/D8 不开始 |

实现位置：`lib/review-contracts.ts`（合同/参数/间隔）、`lib/review-storage.ts`（schema/资格/失效/租约恢复）、`lib/review.ts`（领域服务）、`lib/http.ts`（沿用 Host/Origin/generation 的接口）、`app/review.tsx`（串行前台会话及池操作）、`lib/backup.ts`（schema 3 和旧备份兼容）。

本轮自检修正：反馈 INSERT 的列数；重复揭晓的旧卡版本重放；恢复预览与导出纳入复习表；结束后重读池版本；首次卡片挂载后的焦点；Writing 失败/纠正记录缺正确句时不可练；展示日期/时区与事实时间一致性；导入语境义被用户改写后改标“用户填写”，不继续冒用英文导入标签。旧维护 E2E 的 schema 断言随正式备份版本从 2 更新为 3；未删除其恢复、回收站或数据相等断言。

## 4. 本地启动与试用验收

已有开发服务时刷新页面即可；否则在项目目录执行 `npm run dev`，打开 `http://127.0.0.1:3000/#review`。若使用 `npm start`，先停止旧生产服务，再执行 `npm run build` 和 `npm start`；不要用生产构建覆盖正在运行的同目录开发产物。

1. 进入 Review →“选择近期想练的表达”，按来源选择 3–5 条 P1/P2，确认具体义项后“加入所选表达”。也可从表达详情加入。没有自动整书入池。
2. 使用默认最多 10 分钟/10 张/3 个首次练习表达开始；先应只见表达和真实句子，揭晓后才见释义，再自评或跳过。
3. 暂停、刷新后点继续，确认保留卡与最近成功时长；若刚关闭的另一窗口租约还有效，等约 15 秒后再试。要结束暂停会话，先继续获取写权，再“今天先到这里”。
4. 结束页确认展示数与反馈数不同：跳过/未反馈不计入反馈。检查原 Library 的 Seen/Used 没有增加；不必把上限练满。
5. 设置下载全库 JSON，应为 schema 3 且包含四个 review 数组，不含运行租约。恢复会整库替换，先确认预览警告；请在独立测试库演练，不为试功能直接替换正式学习库。

原用户 3000 服务未被停止；本轮不手动修改其词条、导入或复习池。真实库首次由新代码打开时正常执行带快照的升级，这是产品运行行为；本记录不推断用户库已完成升级，也不宣称已替用户导入或入池。
