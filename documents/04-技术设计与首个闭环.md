# ReadWords 首个闭环技术设计

日期：2026-10-17；依据：PRD v0.2。此阶段不是完整 R0 发布。

> 本文为首个闭环的历史技术设计（schema v1）；备份恢复和数据维护的当前增量见 [09](09-备份恢复与数据维护.md)，当前状态以 [Feature List](FEATURE_LIST.md) 为准。

## 1. 本阶段范围

交付 Source → 手动采集 → Inbox → 保存 → 搜索详情：四类来源、来源编辑/归档、草稿保存/自动保存/忽略恢复、义项候选、原子入库、重复事件确认、Seen/Used 分开统计、来源详情、搜索及筛选。

Review、AI、JSON 备份恢复、表达/Context 编辑及回收站、来源删除留待 R0 后续；OCR/PWA 留 R1。界面明确说明未实现项，不用假数据模拟完成状态。尚未采集任何真实用户数据，默认空库，不自动写演示记录。

## 2. 本地架构

```text
Mac Safari / Chrome
  → http://127.0.0.1:3000
  → Next.js App Router（React + TypeScript + Tailwind CSS）
  → /api/* Route Handlers
  → 领域服务 Store（校验、事务、幂等、版本）
  → Node.js 24 内置 node:sqlite
  → <项目>/data/readwords.sqlite
```

选择 Node 24 内置 SQLite，避免额外原生驱动编译；该模块可能提示实验性警告，需固定 Node 24 运行并保持测试。数据库路径可通过 `READWORDS_DB_PATH` 覆盖，默认目录在项目内以便本机定位。数据库、WAL、SHM、本地环境和构建文件不入 Git。服务只能经回环地址启动，无外部字体、分析、图片或 AI 请求。

dev/build 固定使用 Webpack 模式，避开当前执行环境对 Turbopack CSS 编译子进程端口的限制；Next.js 遥测在 dev/build/start 脚本中显式关闭。依赖版本由 package-lock.json 固定，代码可通过 npm run format / format:check 保持一致格式。

框架路由及数据库 API 依据：[Next.js Route Handlers](https://nextjs.org/docs/app/api-reference/file-conventions/route)、[Node.js SQLite](https://nodejs.org/api/sqlite.html)。实际版本以 package-lock.json 为准。

## 3. 文件职责

- `app/workspace.tsx`：四入口工作空间、来源、列表和表达详情，使用 hash 保留页面位置并支持刷新返回。
- `app/draft-editor.tsx`：Inbox 整理、串行自动保存、失败输入保留、义项及重复确认。
- `app/components.tsx`：可访问的模态框、来源与采集表单。
- `lib/contracts.ts`：共享 DTO、Zod 校验、规范化、日期和听力位置解析。
- `lib/store.ts`：SQLite schema v1 和领域事务，测试可注入独立数据库。
- `lib/http.ts`：API 分发、错误映射、同源写入和本机 Host 校验。
- `app/api/[...path]/route.ts`：Node runtime 适配，显式禁用接口缓存。

## 4. 数据及一致性

核心表为 sources、drafts、expressions、contexts。来源元信息与草稿/语境字段用版本化应用 schema 校验后存入 JSON 文本；高频关联、状态、term、normalized_term、时间和版本使用列及索引。只有本地单用户，当前不设置多租户 owner 表；以后扩展需正式迁移。

Expression 一条代表一个义项，normalized_term 非唯一索引；Context 一条代表一次用户声明的事件。Seen 仅 exposure，Used 仅 output_used，计数从 Context 派生。纠正前后原文、理由和位置不被替换为表达级信息。归档来源不删除 Context。

草稿创建 UUID 充当幂等键；前端重试沿用相同 ID。正式入库在 `BEGIN IMMEDIATE` 事务中检查版本和字段、选择义项、新建 Context、更新草稿结果；成功草稿再次提交直接返回原 expression_id。失败整体回滚。疑似重复事件指纹包含来源、句子、改句、章节、位置和事件类型，由用户确认后才允许重复。

更新使用 version 乐观锁，409 不静默覆盖。自动保存以 650ms 去抖触发，通过串行 Promise 队列更新版本；正式入库前等待当前输入成功持久化。最后成功保存点可刷新恢复；尚未提交的内存输入不能保证进程崩溃恢复，界面有未保存提示、离开确认和复制入口。

SQLite 开启外键、WAL 和 busy_timeout。首次创建通过事务执行 schema v1，`PRAGMA user_version` 标记版本；未知更高版本拒绝打开。后续 schema 变更必须先实施快照迁移，当前不会自动升级已有 v1 库。

## 5. API 契约

| 方法与路径 | 行为 |
|---|---|
| GET/POST /api/sources | 查询/创建来源；创建 ID 幂等 |
| PATCH /api/sources/:id | 带 version 编辑元数据或归档/恢复；类型不可改 |
| GET/POST /api/drafts | 查询未入库草稿/创建草稿 |
| GET/PATCH /api/drafts/:id | 读取/保存草稿；pending 与 ignored 转换 |
| POST /api/drafts/:id/save | version + expressionId 或 newSense + allowDuplicate；原子入库 |
| GET /api/candidates?term= | 返回精确规范化候选，包含义项和历史摘要 |
| GET /api/expressions | q/type/priority/archived/sourceId 筛选、排序、去重 |
| GET /api/expressions/:id | 表达及多 Context、来源和派生计数 |

返回 400 字段无效、403 非本机/跨站、404 不存在、409 冲突/待确认、413 请求过大、415 错误 Content-Type、500 本地存储失败。所有错误为 `{error,code}`，不返回 SQL、原文或凭据；内部日志只记固定错误码。

写请求仅允许 JSON 且 Origin 必须与本机请求 URL 完全一致；回环监听配合 Host 校验阻止跨站与 DNS rebinding 写入。不提供通用代理、远程抓取或外部接口。文本由 React 转义，不使用 `dangerouslySetInnerHTML`。实际上线仍须按用例验证请求边界。

## 6. 已知阶段边界

搜索当前读取本地表达及语境进行子串匹配，适合首个闭环；尚未通过 PRD 的 10k/50k 容量目标，后续需改 SQL 查询/分页并性能验收。日期依设备时区展示，接触日期保留日历值。未使用任何后台外部调用。

此阶段不宣称 FR-01–FR-10 全部完成；已覆盖/未覆盖范围及执行结果见后续测试记录。开发与 E2E 数据分离，E2E 使用独立临时库，禁止在用户数据上清库测试。
