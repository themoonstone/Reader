# 服务器重启与持久化验收

日期：2026-10-18。范围：当前 phrasebud.com 的 preview 部署，不迁移 Mac 正式学习库，不调整认证或购买云资源。依赖 [17 部署记录](17-PhraseBud部署执行记录.md)、[18 备份手册](18-COS异地备份与恢复实施手册.md)。

## 操作合同

1. 检查 Docker enabled/active、三个容器的重启策略、镜像、数据/证书/备份缓存挂载和公开端口，确认当前备份任务没有正在写入。
2. 确认业务维护原为关闭，再开启维护只读；冻结后记录 schema 3 完整性、外键、八张业务表字段摘要及 generation。保存原生一致性快照和受限基线文件。
3. 实际重启 Ubuntu 宿主机，验证 boot ID 改变；等待 Docker 和容器自行恢复，不手工执行 up/start 来掩盖自启动失败。
4. 比较前后容器 ID、镜像、挂载和端口配置，以及数据库业务清单。Review 运行租约按既有重启语义处理，不计入业务摘要。
5. 检查公网 HTTP→HTTPS、受信证书、健康接口、登录页和未登录保护；验证应用到 Supabase 邮箱认证服务连通性。真实账号密码重登仍须用户本人操作，本轮不会获取密码。
6. 校验通过后恢复原维护状态，确认备份服务重启后实际产生新成功标记和远端快照；最终核对磁盘/内存/交换文件。跨日调度和外部失败通知另验收。

如果数据库清单不一致或服务恢复失败，先保留维护和基线排错，不直接覆盖数据库、不删卷、不重建容器。只读验证失败时明确报告实际状态；需要修复则单独记录动作，不能称为自动恢复通过。
