## 4. 自检修正和残余限制

- 创建来源和草稿原先是单语句写入，本轮纳入事务以正确等待/检查维护锁；不是仅在 HTTP 提前看一次状态。
- 一致性导出使用只读事务，不触发 Review 的自动状态变化；原生备份进程不初始化 Store，避免用新进程 ID 使前台会话暂停。
- 保留本地原 no-store 合同；cloud Cookie 更新采用独立客户端和 HttpOnly、安全属性；不把缺配置退回匿名 local。
- 登录表单在水合就绪前禁用输入，防止输入被初始化覆盖；API 401 不自动跳转，原输入保留。
- 页面代理排除 `/api/`，全部业务接口自己鉴权/流式限额，避免 Next 的 10 MB 代理缓冲截断 50 MB 恢复请求；11 MiB 浏览器请求专门覆盖。
- 登录跳转取明确配置 origin；反向代理内部 URL 和伪造转发头不进入 Location。恢复入口请求日志在 Next 开发配置忽略，应用不记录密码/token，Caddy 未开启访问日志。
- restic 使用稳定 host/tag 分组，成功上传/保留/check 后才清理本地历史；成功标记在全部步骤之后写入。崩溃可能留下锁/partial，手册要求停调度并确认无活动作业后再清理。
- 曾发生测试服务启动超时，手动启动同一隔离服务确认健康 200，清理后重跑；不把该轮超时算通过。认证浏览器通过结果与真实认证验收分开。生产冒烟最初使用 fetch 未发送预期 Host，改用可显式设置 Host 的 HTTP 客户端后断言通过。

当前没有正式网址。下一步由用户在自己的认证后台配置项目、唯一邮箱账号和 SMTP，在本机忽略的环境文件填 UUID/邮箱/项目 URL/publishable key，按 15 独立端口验证。真实密码只在自己的表单/后台输入；不需要发给开发助手。服务器购买、域名和异地资源的实际部署在配置与预算确定后进行。
