# ReadWords 云端与多设备升级方案

版本：0.1；日期：2026-10-17。  
状态：规划基线，尚未实施或部署；云厂商、地区、认证服务与预算待落实。  
关联：[PRD v0.5](02-产品需求文档.md) · [Feature List](FEATURE_LIST.md) · [本次文档自检](08-文档一致性自检记录.md)

## 1. 升级后用户应得到什么

用户在 Mac、手机和 iPad 打开同一 HTTPS 地址，登录自己的账号，访问同一份来源、表达和语境。Mac 关机不影响云端使用。已有本地积累迁移一次后，以云端数据库为唯一日常写入库。

第一阶段优先保证手机/iPad 的来源浏览、搜索、P1 筛选与表达详情。Mac 上继续支持已有采集、Inbox 和 Excel 导入。移动端完整录入与导入放在下一阶段适配。

这是单用户私有应用，不开放公共注册、共享表达库或多用户协作。首次云端版本不做断网编辑、离线队列、双向本地同步、自动实时推送或原生 App。多设备访问同一后端，并不要求先开发离线同步系统。

## 2. 当前实际状态

- Next.js 应用与 SQLite 都运行在 Mac；启动脚本只绑定 127.0.0.1。
- `lib/http.ts` 仅允许回环 Host，并校验本机 Origin；当前没有账号、登录会话或身份鉴权。
- `lib/store.ts` 的 schema v2 包含 sources、drafts、expressions、contexts 四张业务表，另有 workspace_meta 保存库 generation；没有 User、ReviewRecord 或 ReviewSession 表。PRD 的领域模型不等于已存在的表结构。
- 本地 JSON 备份恢复、恢复前快照与 v1→v2 升级快照已实现，详见 [09](09-备份恢复与数据维护.md)。维护只读模式、云端迁移工具、部署脚本、监控和云端自动备份未实现。
- 已有少量窄窗口布局验证，不代表手机、iPad、Safari 或 PWA 已验收。
- Excel 导入预览签名密钥仅在进程内；重启后旧预览失效，已确认入库的数据保留。

因此，当前版本不能通过改一个监听地址或上传代码就直接成为安全可用的云端版本。

## 3. 部署路线与选择

| 路线 | 架构 | 优点 | 约束与适用时点 |
|---|---|---|---|
| A：本阶段规划基线 | 单台云服务器 + 单实例 Next.js + 同机持久磁盘 SQLite + HTTPS 反向代理 | 保留当前数据库和大部分领域逻辑，迁移较直接 | 需要维护服务器、磁盘、补丁、备份；不是高可用架构 |
| B：备选 | 托管 Next.js + 托管 PostgreSQL + 认证服务 | 应用与数据库可独立运维，便于后续扩展 | 需改造同步 SQLite API、SQL 方言和事务实现，不能只换连接字符串 |

采用路线 A 作为编写实施方案的默认方向，不代表已经购买服务器或锁定供应商。若用户后续选择 B，应先补数据库迁移设计与验收，C1 产品目标保持不变。

多设备通过 HTTP 后端访问 SQLite；数据库文件只由服务器本机进程操作，不把 SQLite 文件放到网盘或网络共享目录供设备直接打开。[SQLite 网络使用说明](https://sqlite.org/useovernet.html)

Vercel Functions 不提供适合本地 SQLite 的持久共享文件系统；不能把当前文件库随代码上传后作为该路线的日常数据库。这一约束不等于所有托管服务都无法使用持久存储。[Vercel SQLite 说明](https://vercel.com/kb/guide/is-sqlite-supported-in-vercel)

## 4. 目标架构

```text
Mac / 手机 / iPad 浏览器
          │ HTTPS + 登录会话
          ▼
域名 → 反向代理（TLS、请求大小限制）
          │ 仅服务器内部可达
          ▼
单实例 Next.js 生产服务（Node.js 24）
    ├─ 每次请求校验身份、来源与权限
    ├─ SQLite：服务器本机独立持久数据目录
    └─ 备份任务 → 独立故障域的加密备份存储
```

可采用 Docker Compose 管理应用与反向代理；也可使用主机进程管理器。实施时选择一种并记录，不能同时无意启动两个应用实例。生产使用构建产物与 `next start`，不运行 `next dev`；反向代理部署建议参见 [Next.js 自托管文档](https://nextjs.org/docs/app/guides/self-hosting)。

数据库放在发布目录之外，例如主机 `/srv/readwords/data/`，容器通过持久卷挂载，并通过 `READWORDS_DB_PATH` 指向它；此处是未来路径示例，当前 Mac 数据位置没有改变。数据库、备份、密钥不进入 Git、镜像层或公开静态目录。

反向代理只公开 HTTPS 等必要入口，应用端口不直接暴露公网；代理与应用两层均限制上传体积。现有 Excel 文件限制 5 MB，导入接口 JSON 请求限制 8 MB（其他写入接口为 128 KB），考虑 Base64 后应允许合法请求完整通过，不能把代理上限误设为原始文件大小。现有全库恢复预览接口单独限制为 50 MB，不能沿用 Excel 的 8 MB 请求上限；代理配置须保留各端点的不同限额。

## 5. 身份、访问和数据边界

### C-01 私有登录

使用成熟认证实现，优先评估托管认证或 OIDC，不自行设计密码加密、验证码与会话协议。具体提供方、登录方式和会话期限在实施前记录；[Supabase Auth](https://supabase.com/docs/guides/auth) 是候选之一，不是已接入服务。

仅允许配置好的唯一所有者身份进入；认证成功不等于自动获得数据权限。应校验提供方、凭证有效性与稳定用户标识的白名单，拒绝其他已认证账号。拒绝公共注册与匿名访问学习数据。

保护所有业务页面与 GET/POST/PATCH API，特别是搜索、详情、Excel 预览/提交及未来备份下载；不能只隐藏导航。未登录返回登录引导/API 401，非所有者返回 403；静态资源、必要登录回调与无敏感信息健康检查按明确白名单放行。

会话 Cookie 使用 HTTPS 安全设置与适当 SameSite/HttpOnly 策略；支持登出、失效和撤销。读写权限校验与 CSRF/Origin 校验是两件事，均需实现。未来引入其他账号时，必须追加 owner_id 隔离及相应数据库迁移；C1 不把现有全库接口当作已具备多租户能力。

### C-02 域名与代理适配

把当前仅回环 Host 的硬编码改为按运行模式配置：本地模式仍限制本机，云端模式只允许明确配置的正式域名与受信任来源。云端 HTTPS Origin 必须正确识别；只信任受控反向代理设置的转发头，不能相信任意客户端的 X-Forwarded-Host/Proto。不得以删除所有校验的方式修复域名访问。

密钥放服务端运行环境，不能使用 NEXT_PUBLIC_ 前缀或进入日志、JSON 导出、静态资源。AI/OCR 后续仍保持显式单条请求和服务端代理；上云不代表启用后台学习材料分析。

### C-03 设备与在线一致性

云端使用同一数据库。页面首次进入、切回前台或用户主动刷新时重新读取有效数据；有未保存输入时先保护输入，不以自动刷新覆盖。不同设备修改同一草稿时沿用版本检查，冲突保留输入并提示重载，不静默覆盖。

C1 不承诺实时推送。网络中断时明确显示连接问题，不提示保存成功、不清空表单、不把尚在内存的输入称为可靠离线保存。服务端已经提交但响应丢失时，复用已有幂等机制；设备重新加载后应能查到已提交结果。

## 7. 数据迁移步骤与校验

1. **准备**：实现并测试 C0；记录源数据库路径、schema 版本、应用提交、SQLite/Node 版本；复制测试数据在隔离环境演练。当前没有 Review 表就不能声称已迁移复习历史；若迁移前新增该实体，必须纳入导出与核对。
2. **冻结源库**：暂停所有指向该库的写入服务，或启用后端维护只读模式，等待在途事务结束；不要只在页面上隐藏保存按钮。未保存的浏览器输入先保存或复制。
3. **取得一致性备份**：实施时先实现并验证 SQLite 一致性备份机制，再用于迁移；停机备份则在所有连接关闭后进行。WAL 模式运行中不能只拷贝主 sqlite 文件并假定完整；不得手动删 WAL 来“清理”。[SQLite Backup API](https://sqlite.org/backup.html)
4. **建立校验清单**：导出每类记录数量、稳定 ID、引用关系、业务字段摘要；包含 archived 来源、ignored/pending/saved 草稿、Context 的导入元数据及幂等结果关联，不能只统计可见表达。
5. **导入云端**：通过受控运维通道放入专用持久目录或执行版本化恢复，设置最小文件权限，检查 schema 兼容性；不从普通未鉴权上传接口替换数据库。
6. **核对并抽查**：对四张现存业务表及后续新增表核对清单，检查外键和数据库完整性；核对 ID、原句、中文义项/英文语境、等级、归档状态、导入 rowKey 和草稿已保存结果。只比较持久化业务字段，不比较运行态预览密钥。
7. **设备验收**：Mac、手机、iPad 登录同一账号，检查书籍、P1 筛选、搜索与多 Context，确认 Mac 关机后云端独立可用。测试预览重启失效提示，不重复创建已导入事件。
8. **正式切换**：记录切换时间、最终云端记录清单及备份位置，打开云端写入；原本地库保留只读副本并停止日常写入，避免产生两份分叉学习库。

不能用重新上传 Excel 代替全库迁移：表格不包含所有手动记录、草稿和用户修改；也不能用 Git 仓库当作学习数据备份。

## 8. 回退与日常运维

### 回退

- **云端尚未接收新写入**：停止云端写入，确认本地冻结快照仍完整后恢复本地服务。
- **云端已有新写入**：先冻结云端并取得最新一致性备份，核对完整后恢复到兼容的本地实例；旧本地快照不能直接覆盖当前数据。禁止自动合并两份分叉库。
- **应用/schema 版本不兼容**：不得将新 schema 交给旧程序直接启动。使用经验证的兼容版本或专门迁移工具；没有无损回退路径时暂停写入并保留两端快照，先恢复可用环境再决策。

### 备份与维护

规划默认：每天一份一致性自动备份，保留最近 7 份日备份和 4 份周备份；发布和迁移前另做快照；备份加密并存放在独立于应用服务器的故障域。建议恢复点目标 RPO ≤24 小时、恢复时间目标 RTO ≤4 小时，均为待演练验证的目标，不是已实现 SLA。

至少每月演练一次恢复到隔离目录，记录校验结果、耗时及最后一次成功备份；失败时通知维护者。磁盘、备份失败、服务异常、证书续期和预算额度应有监控或告警；学习原文和密钥不进入普通日志。

部署前确定负责人。生产代码、数据和配置分开，更新应用不得重建/清空数据卷；若有 schema 变更，先快照再迁移。当前内存预览密钥继续采用重启失效策略，提示用户重新上传；不得为无缝预览而开放多实例共享文件写入。
