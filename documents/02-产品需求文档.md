## 1. 产品定义与目标

**ReadWords 是把用户真实读过、听过、写过的英语，沉淀为个人表达能力的轻量学习系统。**

副标题：Learn from what you actually read, hear, and write.

### 1.1 目标用户与场景

当前已实现版本及原 R0 本地基线以 Mac 个人本地使用为范围；后续 C 阶段增加手机/iPad 的私有云端访问，范围见 §2.3，不能把规划当成现有能力。产品面向个人英语学习者：持续阅读英文书籍、文章，收听播客或视频，并有日记、工作写作等输出需求。用户愿意人工筛选值得留下的表达，不希望维护复习欠账。

| 场景 | 用户问题 | 产品应提供的结果 |
|---|---|---|
| 阅读 | 生词和好表达散落在笔记中 | 快速保存表达、原句与出处，后续整理 |
| 听力 | 听不懂或误听，之后找不到原材料位置 | 保存实际听到的句子、来源、时间位置与误听说明 |
| 写作 | 想表达但不会，或表达被纠正 | 保留失败表达与改进表达，供主动回忆 |
| 重复遇见 | 同一表达在多处出现，历史割裂 | 向同一义项追加接触记录，看到来源与使用历史 |
| 复习 | 传统待办式复习造成压力 | 自选 10/20/30 分钟，随时结束，无欠账提示 |

### 1.2 产品原则

- 优先保留真实上下文与来源；缺失内容标注缺失。
- 阅读、听力、写作、手动记录共用表达库和复习入口。
- 用户决定保存、学习优先级与归档；AI 只给建议。
- P3 记录即可；允许忽略、降级及归档。
- 复习按时间预算组织，不展示逾期债务、任务清零率或排名。
- 保存、被纠正和反馈 Easy 均不能推断“已经掌握”。

### 1.3 成功标准

R0 必须通过本文件所有 MUST 需求对应的验收用例。产品可用性目标为：用户能独立完成“手动采集 → Inbox 确认 → 保存 → 搜索 → 复习 → 备份恢复”闭环。

首轮可用性评估建议邀请 5 名目标用户，至少 4 名在无操作指导下完成该闭环；记录失败点、耗时中位数及 P90。样本仅用于发现问题，不用于声明总体学习效果。不得把记录量、复习次数或自评反馈宣传为语言能力提升。

## 2. 范围与发布阶段

开发级别：**MUST**＝该阶段交付前必须满足；**SHOULD**＝不阻断核心闭环的改进；**LATER**＝不在当前阶段。学习优先级仅使用 P1/P2/P3，二者不可混用。

| 阶段 | MUST | SHOULD / 后续 |
|---|---|---|
| R0 手动学习闭环 | 四类 Source；手动采集和 Inbox；Expression + 多 Context；Why Saved；精确重复候选及人工归属；AI 语境释义及优先级建议；三种 Review；Search；Mac 桌面自适应界面；编辑归档回收站；JSON 备份恢复 | 基础计数可随详情显示，不单设统计大屏 |
| R1 采集与使用体验 | Mac 图片选择 OCR；Mac PWA 安装体验；CSV 导出；简单统计 | 云端账号与设备扩展按独立 C 阶段规划，不由 PWA 隐含承诺 |
| R2 长期价值 | 模糊跨来源匹配；升级建议；显式选择的写作纠正内容导入 | 多来源统计、用户数据支持的个性化建议 |

R0 的精确重复候选不属于 R2 的语义匹配。多 Context 数据模型和真实计数从 R0 起就必须存在。OCR 统一在 R1，消除原稿中的版本冲突。

### 2.1 明确不做

R0/R1 不包含完整词典、考试词库、阅读器、播放器、音频上传/切片、字幕自动提取、语音识别、听写、发音/作文评分、整篇日记批改、聊天集成、社区、排行、打卡惩罚、游戏化、完整 SRS 配置、Anki 同步、浏览器扩展、微信小程序和原生 App。

R2 的“写作导入”仅导入用户选定的结构化纠正条目，不等于自动批改日记。

## 3. 术语与信息架构

| 术语 | 定义 |
|---|---|
| Source | 真实材料的来源记录，类型为 Reading/Listening/Writing/Manual |
| Expression | 规范表达的一个义项，是学习目标；同形异义允许分别建条目 |
| Context | 某表达的一次真实接触/输出事件，属于一个 Source 和一个 Expression |
| CaptureDraft | 未正式入库的采集草稿，是 Inbox 的数据基础 |
| P1 | 主动掌握目标，适合回忆练习 |
| P2 | 理解目标，默认识别练习 |
| P3 | 记录目标，不进入复习 |
| ReviewRecord | 一次已提交的复习反馈事实 |
| ReviewSession | 一次时间预算会话及其进度 |

一级导航固定为 **Library / Inbox / Review / Search**，Settings 位于菜单。全局“+”进入四类采集方式。不增加独立阅读、听力或写作训练入口。

Library 管理 Source，筛选 All/Reading/Listening/Writing/Manual，默认最近更新优先；Source 详情列出关联表达。Search 承担跨来源表达检索。最近使用列表不替代完整来源列表。

## 4. 数据与业务规则

### 4.1 通用约束

- ID 稳定且不复用；所有持久化记录具备创建/更新时间及版本号。
- 时间点以 UTC 存储，按设备时区展示；来源日期是日历日期，不随时区偏移。
- `source_type` 从 Source 推导，不在 Context 独立维护可冲突值。
- 数量从有效事件计算；若缓存，必须可重建，事务中保持一致。
- 来源、原句、页码、时间戳不允许 AI 补造；缺失字段显示“未提供”。
- 以五个核心领域实体 User/Source/Expression/Context/ReviewRecord 为基础，允许草稿、会话、AI 建议等支撑对象；不限制数据库表数。单用户 R0 允许只有一个本地所有者。

### 4.2 Source

| 字段 | 规则 |
|---|---|
| id / owner_id / type | 必填；类型四选一，已有 Context 后禁止直接改类型 |
| title | 必填，去首尾空白后 1–200 字符；允许同名，不按标题自动合并 |
| author_or_speaker / url | 可选；URL 仅接受 http/https，不自动抓取内容 |
| source_date | 可选；Writing 默认设备当天日期，可修改 |
| reading_status | 仅 Reading 可用：want_to_read/reading/finished/paused；默认 reading |
| current_chapter | Reading 可选文本，与单个 Context 的 chapter 分开 |
| format / duration_seconds | Listening 可选格式和非负整数时长 |
| lifecycle | active/archived/deleted，与阅读进度分开 |
| metadata | 扩展字段，禁止代替必需业务字段；封面后续再定 |

Writing 默认标题“Journal · YYYY-MM-DD”，可改为 Essay/Chat Practice/Work Writing 等。快速录入可创建当天来源；同日同标题已有记录时提示复用，不能静默猜测。无明确出处可使用默认 Manual 来源“未分类手动记录”。

### 4.3 Expression

| 字段 | 规则 |
|---|---|
| term | 必填，去首尾空白后 1–200 字符；保留用户展示形式 |
| normalized_term | Unicode NFKC、去首尾空白、连续空白压为一格、英文字母小写；保留标点，不自动词形还原 |
| type | word/phrase/collocation/chunk/sentence_pattern；默认 chunk，可改 |
| sense_label / meaning | 入库时须有中文或用户可理解的义项说明；1–1000 字符；可用 meaning 兼任义项说明 |
| simple_alternative | 可选，明确为辅助理解；不保证所有语境等价 |
| learning_priority | P1/P2/P3；新建默认 P2，用户提交时确认 |
| lifecycle | active/archived/deleted；不使用 Familiar 作为生命周期 |
| next_review_at / last_reviewed_at | 调度字段，可空，按复习规则更新 |

同一规范化表达可有多个义项。匹配只返回候选，不执行无条件唯一约束或强合并。例如 `bank` 的“银行”和“河岸”必须允许独立保存；`carved out` 与 `carve out` 不做自动词形合并。对写作，term 保存学习目标的规范表达，原句中实际出现形式另存 Context。

### 4.4 Context

| 字段 | 规则 |
|---|---|
| expression_id / source_id | 正式入库必填，不能引用已删除来源 |
| event_kind | exposure / output_failed / output_corrected / output_used，必填 |
| original_sentence | 用户提供的原句，可空；至多 10,000 字符 |
| target_surface | 该事件中目标表达的实际形式，可空；允许与 term 不同 |
| target_range | 在学习用句中的连续字符区间，可空；必须校验与实际文本一致 |
| meaning_in_context | 该次语境含义，正式入库必填，不能用其他义项自动覆盖 |
| chapter / page_label | 可选文本；页码允许罗马数字、电子位置等，不能强制仅整数 |
| timestamp_seconds | Listening 可选非负整数；输入 mm:ss 或 hh:mm:ss 后规范化。若已知时长，不得超过时长 |
| occurred_on | 可选真实接触日期；不以创建时间冒充历史接触时间 |
| why_saved | 单选：did_not_understand/misheard/useful/could_not_produce/writing_correction/want_to_use/other；默认 useful，可改 |
| note / misheard_text | 可选备注和误听内容；other 时 note 必填 |
| original_expression / corrected_expression | 写作失败片段与目标片段；output_corrected 时均必填且不得相同 |
| corrected_sentence | 可选完整改进句；由用户输入或明确采纳的建议提供 |
| intended_meaning | 可选用户想表达的意思，用于 Writing Recall，不得直接暴露目标英语 |
| origin / lifecycle | manual/ocr/import；active/deleted；保留 AI 采纳来源标记 |

Reading/Listening 默认 exposure；Writing 必须选择“表达失败 / 获得纠正 / 已自主使用”，默认表达失败；Manual 显式选“遇见 / 想表达但不会 / 已自主使用”。纠正事件的来源必须是 Writing；误听原因仅适用于 Listening。

例：用户写 `The long commute costs my energy.`，得到改句 `The long commute drains my energy.`。保存 term=`drain my energy`、original_expression=`cost my energy`、corrected_expression=`drain my energy`、corrected_sentence 为完整改句、target_surface=`drains my energy`、event_kind=`output_corrected`。此时 Used 仍为 0。

### 4.5 计数口径

- Context 总数：该 Expression 下 active Context 数量，四种事件均计入。
- Seen：event_kind=exposure 的有效 Context 数量，表示主动记录的接触次数，不等于现实中实际出现频次。
- Used：event_kind=output_used 的有效 Context 数量，是用户声明的自主使用次数；纠正、失败、复习均不计入。
- Sources：不同有效 source_id 数量；来源类型数另外计算，两个不同 Reading 来源也算两个来源。
- First recorded：最早有效 Context 的创建时间；First encountered 仅从有 occurred_on 的事件取最早日期，并注明记录可能不完整。
- 删除/恢复 Context 后重算；Source 归档保留证据，相关计数不变；删除事件和回收站记录不计入。

### 4.6 状态、编辑与删除

| 对象 | 状态与转换 |
|---|---|
| CaptureDraft | pending → saved 或 ignored；ignored 可恢复 pending；saved 不可再次提交 |
| AI 请求 | idle → running → succeeded/failed/cancelled；不改变草稿入库状态 |
| Expression | active ↔ archived；两者均可移到 deleted；回收站可恢复 |
| Source | active ↔ archived；仅无有效 Context 且无 pending/ignored 草稿引用时可移到 deleted |
| Context | active ↔ deleted；删除最后一个 Context 不自动删除 Expression，需显示“无上下文” |
| ReviewSession | running ↔ paused → ended；预算到达或主动退出进入 ended，不能再追加反馈 |

Expression 归档后不进入复习，仍可按开关搜索。Source 归档仅影响来源列表，不自动改变关联表达复习资格；新增 Context 前须恢复来源。删除 Expression 时其有效 Context 一并移入回收站，历史 ReviewRecord 保留但不参与当前统计。恢复时仅恢复本次级联删除的 Context；若来源仍已删除，须先恢复来源。

R0 不提供永久清空回收站，不自动定期清理。ReviewRecord 不可编辑历史结果。Context 的归属可以改到另一未删除表达/来源，需显示目标并一次事务提交；调度历史不迁移。R0 不做批量合并/拆分向导，用户可通过修改归属修正误匹配。

### 4.7 草稿、复习与建议的最小持久化信息

| 对象 | 最小字段与约束 |
|---|---|
| CaptureDraft | id、owner_id、采集类型、可空 source_id、用户原始输入、Context 待填字段、拟用优先级、候选 expression_id、pending/saved/ignored、input_version、提交幂等键、保存后的 expression_id/context_id、创建/更新时间；正式入库字段未齐全前允许草稿存在 |
| ReviewSession | id、owner_id、budget_seconds（600/1200/1800）、active_elapsed_ms、running/paused/ended、started_at、进度保存时间、ended_at、结束原因（预算/主动/无题）、当前展示卡及答案揭晓状态、每表达出现次数、Forgot 重试门槛进度、写入租约/版本；一次只允许一个 running 会话 |
| ReviewRecord | id、owner_id、expression_id、context_id、session_id、card_id、review_type、result、reviewed_at、反馈前后 next_review_at、题面/答案最小快照；card_id 唯一防止重复提交，快照仅本地保存并随备份导出 |
| AISuggestion | request_id、draft_id、input_version、请求状态、provider/model、生成时间、结构化建议、采纳字段与时间；保存用户采纳的建议供追溯，不持久化密钥；R0 不依赖云端会话历史 |

会话中切换的卡若因表达被归档/删除、优先级变化或 Context 被编辑而失效，禁止提交旧卡，保留已提交历史并重新选卡。ReviewRecord 引用的 Context 即使被删除或改归属，历史仍按快照和原 expression_id 展示，不能随现有 Context 重写历史。没有反馈的跳过/退出不生成 ReviewRecord，也不改变间隔。

所有备份对象保留逻辑关联所需的稳定 ID；恢复校验须识别已删除对象和历史引用的合法性，不能把合法回收站引用当成悬空引用。

## 5. 功能需求与验收条件

以下 FR 均为 R0 MUST，明确标为 R1/R2 的子项除外。

### FR-01 来源管理

用户可新建、编辑、筛选、归档、恢复四类 Source，查看关联表达。表单只展示该类型相关字段；错误贴近字段显示，保留已填内容。

**验收**：四类来源均能保存并出现在 All 和对应筛选中；无标题无法提交；有引用来源不可删除并显示引用数量及处理入口；Reading 的 Finished 不会归档 Expression。

### FR-02 手动采集与 Inbox

全局“+”选择来源类型，可选既有来源或内联创建来源。至少填写 term 才能保存草稿；原句、位置及释义可后补。Writing 可先填目标改进表达。每次成功手动采集只生成 pending 草稿，显示“已加入 Inbox”。FR-12 的已整理表格在批量预览并明确确认后允许直接入库。

Inbox 默认按创建时间倒序显示 pending，提供来源筛选、继续整理、忽略、查看并恢复忽略项。编辑后自动保存草稿，保存中/失败/已保存可辨别；失败保留当前表单并提供重试与复制文本入口。离开有未持久化修改的页面时提示；已持久化内容刷新后可恢复。

**验收**：只有 term 的记录可进 Inbox，但不会进入复习；强制刷新可找回最后一次成功持久化的草稿；忽略不生成 Expression 或 Context；双击采集提交只创建一条草稿。

### FR-03 确认入库与精确重复候选

整理页展示原始证据、AI 建议、Source、Why Saved、学习优先级与义项。正式保存要求 term、有效 Source、语境释义、Why Saved、事件类型及学习优先级齐全；允许缺原句，但显示“缺上下文，部分练习不可用”。

按 normalized_term 查询所有未删除同形表达，显示义项、来源摘要与归档状态。用户明确选择“追加到此义项”或“新建义项”。不替用户确认同义。归档候选允许追加 Context，但保持归档，除非用户显式恢复。每次新事件创建独立 Context。

追加操作采用既有 Expression 的优先级；若用户要修改，展示明确选项，不能用草稿默认 P2 覆盖既有 P1。连续新建不同草稿但来源、原句、位置、事件类型相同且目标相同的记录提示“可能重复”，用户可确认这是另一次事件。

**验收**：同义项追加不增加 Expression 数；同形异义可新建；提交失败不产生孤立对象；同一 saved 草稿重复提交返回原结果，Context 只增加一次。

### FR-04 表达详情与历史维护

展示目标表达、义项、类型、优先级、辅助替换、Seen/Used/Context/Source 数量及 Context 时间线。时间线展示真实事件种类、来源、原句、位置与保存原因；日期缺失时显示记录日期并标注。写作保留失败与改进内容。支持编辑、追加 Context、修改归属、归档及回收站恢复。

**验收**：同一义项可同时展示 Reading、Listening、Writing 和 Manual 事件；写作纠正不会增加 Used；删除、恢复和修改归属后各页面计数一致；不显示“AI 判定已掌握”。

### FR-05 AI 辅助整理

所有 AI 请求经 Mac 本机服务端代理。打开页面、刷新、导入备份、新增或修改 Context 均不得自动发起外部请求；R0 不提供批量 AI 操作、定时分析或后台补全任务。

用户在单条草稿上点击“获取建议”后，发送当前 term、用户勾选允许发送的句子/写作字段、Source 类型和本地计算的事件数量。来源标题、URL、整本材料、其他日记及完整用户历史默认不发送。首次使用展示实际待发送字段、提供方及费用说明，用户确认后再发送；之后仍可逐次查看并取消。

输出结构：语境释义、简单替换、表达类型、建议优先级、简短理由。缺上下文时明确提示推测，不声称语境已确定；无证据时不输出精确 CEFR、词频、掌握率或用户行为事实。Writing 纠正默认建议 P1，普通 Reading/Listening 默认 P2，均仅为建议。

AI 建议与用户输入并排显示，逐字段采纳或拒绝；不得覆写原句、来源、位置或已确认值。原文作为数据处理，不能执行其中的指令、链接或工具操作。用户在请求过程中改了输入，旧结果标为过期，需重新请求，不能自动应用。

单次请求 30 秒超时，无自动无限重试；失败、限额、断网及未配置时保留草稿，允许纯手工完成全部闭环。存储请求 ID、输入版本、提供方/模型、时间与采纳字段以便追溯；日志不记录完整原句和凭据。提供取消按钮；结果未返回前不得阻止保存。

**验收**：模拟超时、非法结构、过期结果和限额均可继续手工保存；提示注入文本不触发任何操作；拒绝建议后用户原文不变；重复点击只产生一个进行中请求。

### FR-06 复习练习生成

候选为 active、P1/P2、至少有一种有效题型的 Expression；P3、归档和回收站排除。按每个表达现有 Context 生成确定性卡片，不在会话中临时调用 AI 判题。

| 模式 | 资格与题面 | 答案 |
|---|---|---|
| Recognition | 有真实原句、有效 target_range/target_surface 和语境释义；展示原句并高亮目标实际形式 | meaning_in_context，可附来源位置 |
| Recall | P1，有学习用句、有效连续目标区间及不泄露答案的中文义项/意图提示；挖空目标 | 实际形式及 term，注明可接受的表达不止一种，用户自评 |
| Writing Recall | P1、Writing，有 intended_meaning，且有有效纠正句或自主使用句与明确目标 | 对应完整句及目标片段，标记句子来源 |

学习用句优先使用用户提供/明确采纳的 corrected_sentence，否则使用真实 original_sentence。纠正后的目标不在原句中时禁止对错误句挖空。目标多次出现时用户必须确认选哪个区间；不连续表达或形态未对齐时不生成 Recall。未确认的 AI 句子和释义不能作为答案。

题型优先顺序：P1 有合格 Writing Recall 时用该模式，否则合格 Recall，否则 Recognition；P2 只用 Recognition。相同模式多个 Context 按上次使用最早优先、从未用过优先，再按创建时间与 ID 排序。缺少所有题型时显示“补充上下文后可复习”入口，不生成空卡。无有效范围的记录仍可搜索和保存。

**验收**：`drain my energy` 能使用已确认改句中的 `drains my energy` 生成题目；缺原句表达不生成 Recognition；答案只在用户点击“显示答案”后显示；先揭晓答案才能反馈。

### FR-07 时间预算与 Soft SRS

用户选 10/20/30 分钟开始。计时从首张卡显示起，只累计页面可见且会话 running 的前台时间；手动暂停、切后台和锁屏均暂停，不计入有效练习时间。预算到达后保留当前卡供查看，但禁用新反馈和下一题，显示结束入口。用户可随时结束。

候选选择与调度采用以下最小确定规则（本版基线参数，后续调整须更新验收）：

1. 新入库且具备题型的 P1/P2：next_review_at=保存时刻；无题型者保持空。
2. 取 next_review_at ≤ 当前时间的合格表达；尚未到期者不提前填满时间。排序为：本次 Forgot 的到期重试、P1、P2；各组按 next_review_at、created_at、ID 升序。
3. 答案揭晓后自评 Forgot/Familiar/Easy。原子写 ReviewRecord 与调度：Forgot → 当前时间 + 10 分钟；Familiar → + 3 天；Easy → + 7 天。间隔不累乘，不宣称完整 SRS。
4. 同一表达每会话最多出现两次；只有本次首次反馈 Forgot 且至少经过 3 张其他表达卡时，才允许到期重试。若未达条件，不能强行重复。第二次反馈即使 Forgot，也不再在同会话出现。
5. 无可选卡立即结束；允许未用满预算，不创建虚假学习任务。三天未打开也仅展示时间选择和可选练习，不出现逾期数量。
6. P1↔P2 不重置历史，下一次出题按新优先级生成；改为 P3 或归档即排除。P3→P1/P2、恢复归档、首次补齐题型时 next_review_at=当前时间。丢失全部题型则置空；仍有题型时编辑不重置间隔。

每张卡有稳定展示 ID；一次反馈提交只产生一条记录。刷新后可恢复会话、累计前台时间和最后成功提交位置；暂停时间不补算。异常关闭无法精确确定时间时，以最近一次成功保存的进度为准，计时至少每 5 秒保存一次。跨标签页仅允许一个可写复习会话，第二页提示返回正在运行会话。

**验收**：计时、暂停、重复提交、无题、错过多天、最后一刻反馈与预算到期竞争均满足规则；以服务端/本地事务接受时刻判断是否仍可提交，预算到期后的提交不写入；不展示欠账。结束页仅显示本次有效时长、已提交反馈数和可选反馈分布，不给记忆率。

### FR-08 搜索

搜索覆盖已入库 Expression.term/meaning、Context.meaning_in_context/original_sentence/corrected_sentence、Source.title；不包含 pending/ignored 草稿。英语大小写不敏感，空格按规范化处理，中文按连续子串匹配；R0 不承诺模糊、词形或语义搜索。

默认排除 archived/deleted Expression；提供包含归档开关和来源类型、学习优先级筛选。Source 归档不隐藏 active Expression。排序按 term 完全匹配、term 前缀、term 包含、其他字段匹配四组，再按 Expression 更新时间倒序、ID 升序；同一表达只出现一次。空输入显示最近更新的表达；无结果提供新建入口，不自动创建。

**验收**：能从英文表达、中文语境释义、来源名、原句找到目标；Manual 可筛选；一个表达的多个 Context 命中不会重复展示；能定位匹配字段及 Context。

### FR-09 数据备份与恢复

Settings 提供 JSON 导出，包含 schema_version、exported_at、来源、表达、Context、草稿、复习记录、会话进度及 AI 已采纳来源信息；含归档和回收站记录，不含密钥、缓存、服务日志及未返回的请求。全库一致性快照导出，文件包含敏感写作材料，下载前说明。

R0 恢复采用“替换本地库”，不提供自动合并。先解析和校验版本、大小、ID 唯一性、引用、字段、计数和时间，展示各类数量；自动生成当前库的恢复前快照，快照成功后要求用户明确确认替换，事务成功才生效。失败不改原库，不自动调用 AI；导入的 active 会话转为 paused，进行中的 AI 请求标为取消。

仅支持当前 schema_version；其他版本明确拒绝并保留原库。建议 R0 导入文件上限 50 MB，超限提示；恢复前必须有空间存放快照和新数据。拒绝从导入文本执行 HTML/脚本或外部链接。

R1 CSV 每行一个 Context，携带 expression_id/context_id、表达、义项、语境释义、优先级、来源类型和标题、句子、位置、原因、事件种类、写作前后内容；无 Context 表达保留一行并留空 Context 字段。CSV 是阅读/迁移格式，不能完整恢复复习历史。对可能被表格解释为公式的单元格做安全转义并说明。

**验收**：JSON 往返恢复后稳定业务字段、ID、引用、计数和历史一致；不比较导出时间、派生缓存及运行态字段；损坏、超限、未知版本、重复 ID 和悬空引用均拒绝且不改变原库。

### FR-10 Mac 桌面界面与操作反馈

本条描述 R0 目标：在 Mac 浏览器完成采集、Inbox、Review、Search、来源管理与多个 Context 编辑，布局适配桌面窗口缩放。Review 和 Context 编辑目前未实现；C 阶段移动端范围另按 CF-05/CF-09 验收。R0 不承诺批量整理；批量选择操作待后续评审。提供加载、空态、失败重试、保存成功、无候选、未配置 AI 和存储空间不足状态。

支持键盘访问所有操作、明确焦点、表单标签及 macOS VoiceOver 名称；主操作目标至少 44×44 CSS 像素；错误不能仅用颜色表达。常规验收窗口为 1280×800 CSS 像素，至少支持 1024 CSS 像素宽；200% 页面缩放下核心表单和复习内容须重排且可完成操作，不依赖整页横向滚动。手机窄屏不作为 R0 验收要求。

**验收**：四个一级入口、四类采集在目标 Mac Safari/Chrome 中均可访问；键盘能完成手动保存和复习；连续点击不产生重复记录；保存失败仍保留输入。

### FR-11 后续 OCR、PWA 与升级建议

**R1 OCR**：Reading 支持从 Mac 选择单张 JPEG/PNG/WebP 图片（含截图），上限 10 MB；显式点击“识别”后经本机服务端代理调用。取消、超限、方向错误、识别失败均可回退手输；不扫描文件夹或后台批量识别。手机拍照、相机直采与 iOS 图片转码不在当前阶段范围。识别文本先展示供用户修正，用户选择表达并确认原句后才形成草稿；不得自动入库或猜测章节页码。图片默认不永久保存，成功或取消后删除临时副本；如使用外部服务，发送前说明提供方、内容与保存政策，政策未核实不得上线。

**R1 PWA**：提供图标、manifest、安装引导与独立窗口展示；安装支持按实际浏览器能力验收。PWA 界面仍连接本机服务及 SQLite，不复制一套浏览器业务库；本机服务运行时断外网仍可使用本地核心功能，AI/OCR 离线明确不可用。本机服务停止时显示启动引导/连接失败状态；安装 PWA 不代表它能自行运行后端。更新必须先保存草稿、提示用户再刷新。R0 没有账号，因此不承诺“保持登录”；未来账号另定义会话期限。PWA 不隐含同步。

**R2 匹配与升级**：允许词形或语义候选，展示匹配依据，始终由用户确认。P2 在有效 exposure ≥ 3 且不同 Source ≥ 2，或新增 output_failed/output_corrected 事件时可提示 P1；不强制升级。同一证据版本拒绝后不重复提示，只有新有效事件才可再建议。多来源只能说明接触记录更多，不能等同高频或掌握。

### FR-12 已整理 Excel 的严格 P1 导入（本次增量）

用户已于 2026-10-17 同意按预览方案导入已整理的 Bringing Up Bébé 表格，本次仅导入严格版 P1。入口位于顶部“导入 Excel”，不新增一级导航。

- 接受本机上传不超过 5 MB 的 .xlsx；解析在本机服务端完成，不调用 AI、不上传外部服务。
- 从具备 Circled item 和复习优先级（严格版）的章节明细读取数据，跳过统计、P1 汇总及去重复习表；P2/P3 仅参与总数/等级冲突检查，不入库。
- 预览逐组显示词条、中文义项、英文语境解释、章节/Excel 行号、句子、页码、严格等级理由与复习目标。按规范化实际词条和完全一致的中文义项分组，不做词形还原；允许每行独立保存、组内合并、追加已有 P1 或暂不导入。
- 已有同词默认跳过，用户需明确选择；既有 P2/P3 不自动升级，归档表达不直接追加。其他等级冲突保留提示，最终以已确认的严格 P1 明细为准。
- 中文列是词典义项，保存在 Expression.meaning；原表英文语境解释保存在 Context.meaning 及导入元数据，详情明确标注语言和性质，不冒充中文语境翻译。
- 不用复习搭配覆盖原词条；音标、词性、词典英文解释、原等级、原表次数、归一词条和文件/工作表/行号保留为导入元数据。Why Saved 原表缺失，明确显示默认 useful。事件为阅读 exposure，Used 不增加。
- 只为每行真实明细生成一条 Context，不按出现次数重复创建事件；缺失页码和节选保持原样。确认批量义项与等级后直接入库，不重复逐条进入 Inbox。
- 预览不写业务库；预览有效期 30 分钟，服务重启或过期后重新上传。提交使用服务端签名预览，不能由客户端修改条目或导入 P2/P3。
- 整批写入采用事务；任一失败全部回滚。相同来源下相同章节/行号/词条/原句/页码的已导入明细跳过，文件改名不影响去重；源内容改变时重新检查，不以文件名作为去重依据。

**验收**：本地样本预览显示 1,098 条明细、P1/P2/P3 为 120/514/464；空库按默认分组确认后新增 112 个 P1 表达、120 条 Context，P2/P3 为 0。预览不写库、签名篡改被拒绝、重复导入不增量、失败回滚、已有低等级不自动升级。112 是保守义项分组数，不是表内 101 个训练目标的口径。

## 8. 统计与展示限制

R0 详情仅展示定义明确的事件计数；R1 汇总默认统计 active Expression，按 P1/P2/P3 分组；Source 按 active Source 和四类分组，明确归档未计入。跨来源统计用不同 source_id ≥2；“自主使用过的 P1”指 active P1 中存在有效 output_used 的表达数。

不得展示连续打卡排名、欠债数量、任务清零率或伪精确记忆率。Review 会话卡次数可能大于去重表达数，两者必须分开命名。

## 9. 技术约束与实现边界

R0 采用原稿建议的 Next.js、TypeScript、Tailwind CSS 与 Next.js API 作为实现基线，SQLite 存储于用户 Mac。本地服务承担数据读写、事务、备份恢复及外部 AI/OCR 代理；浏览器不接触提供方密钥。服务默认仅监听回环地址，写入及代理接口校验请求来源并防止跨站调用，禁止作为任意 URL 转发代理。具体目录和凭据读取方式在技术设计中记录；密钥不写入业务库或 JSON 备份。

本机服务运行且数据库可用时，断外网仍须支持启动界面、采集、整理、搜索、复习和 JSON 备份恢复；外部能力显示不可用并保留输入。停止服务后数据文件保留，重启后可继续使用；首版须交付 Mac 本地启动、停止、数据目录定位及备份恢复说明。若改为托管服务，须先变更身份、数据位置和备份责任需求。

实现前需补充数据迁移策略、幂等键、事务范围、AI/OCR 适配协议、性能样本及目标部署图；这些属于技术设计产物，不应把数据库表数和框架名称当作产品验收结果。
