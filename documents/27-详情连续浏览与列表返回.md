# 详情连续浏览与列表返回

日期：2026-10-24。范围：来源表达列表、Search、表达详情与浏览器历史；不改变数据库、搜索匹配、导入或复习规则。

## 1. 行为合同

1. 从来源表达列表进入详情，只连续浏览该来源当时显示的表达；从 Search 进入，只浏览当时的搜索结果。保留关键词、来源类型、P1/P2/P3、包含归档开关和显示顺序。同词不同义项按表达 ID 分开，同一表达只出现一次。
2. 提供“上一条”“下一条”和位置提示，第一条不能向前、最后一条不能向后，不循环。连续浏览按进入时的 ID 顺序，不因阅读、编辑更新时间而突然重排；新增符合条件的表达在返回列表重新进入后加入序列。
3. 并行核对原条件下的有效结果，删除、归档后被筛除、移出来源或不再匹配的表达不能成为下一条；保留原顺序。当前表达失去资格时仍可阅读当前详情并继续向两侧查找有效条目；位置提示明确其已不在结果中。核对失败不猜测下一条，保留正文和返回入口，可重试。核对不能阻塞详情原文读取。
4. “返回来源列表”或“返回搜索结果”恢复筛选并定位刚看过的表达；若该表达已不存在，尝试原序列中邻近的有效项，再回退原滚动位置。返回后列表按服务器最新排序显示。
5. 上下文保存在当前标签页的浏览器历史条目，刷新和浏览器前进/后退可继续使用；不写入学习库，不把搜索词和列表 ID 附在分享网址中。不存原文句子或认证资料。直接打开/复制详情网址、新标签页或从 Inbox、回收站进入，不继承其他列表，提示从列表进入后可连续浏览，并保留“返回表达库”。
6. 输入尚未保存时沿用离开确认；取消必须保留当前页和输入。列表筛选请求未完成时不允许点旧结果，快速连续操作以最后一次导航为准。手机控件换行且无横向溢出。

## 2. 实现步骤

- 先确定以上合同，再实现历史上下文校验、列表请求状态及位置恢复。
- 接入详情前后导航与并行有效结果核对，维护操作保留或返回对应列表。
- 补充纯逻辑与浏览器回归，更新 PRD、Feature List、同源指南和索引。

## 4. 实现与自检证据

实现位于 `lib/browse.ts` 和 `app/workspace.tsx`。历史数据有版本、来源路径、筛选类型、唯一表达 ID、定位锚点和非负滚动值校验；无效或与当前网址不符的历史数据回退普通详情。导航上下文仅存浏览器历史，不使用跨标签共享缓存或学习库字段。

详情每次切换/刷新/重试会并行读取原条件下的有效 ID，并与进入时的序列求交集；使用 `GET /api/expressions?...&idsOnly=1`，沿用搜索的匹配、权限和排序，响应仅包含 ID、禁止缓存。它减少传输量，不声称优化了数据库搜索算法。正文仍独立于来源、Inbox 和列表核对请求。结果请求有有效期标记，旧响应不能覆盖新条件；核对完成前前后按钮禁用。

返回列表等待最新结果再定位；当前锚点缺失时先找原序列后方邻居，再找前方邻居。保存维护操作后保留对应浏览上下文；删除表达或将语境移到其他义项后返回原列表。页面切换先进入加载状态再挂载新表单，防止瞬间挂载又卸载而丢失刚选择的上传文件。

## 5. 使用与人工验收

1. 在 Library 打开一本书，可先选 P1；点任一表达后用“上一条 / 下一条”继续看，顶部应显示“当前来源”和序号，不能进入其他来源专属词条。
2. 点“返回来源列表”，确认 P1 等筛选仍在、刚看的词条已定位。若该词条已不符合筛选，定位其原序列邻居。
3. 在 Search 输入关键词并组合类型/优先级/归档筛选，打开词条后应标注“搜索结果”，顺序与刚才的结果一致；刷新后再试下一条和浏览器返回。
4. 直接在新标签打开详情链接，只提供返回表达库及从列表进入的提示；不能借用上次的搜索范围。编辑尚未保存时，取消离开应保留输入。

本地启动沿用 `npm run dev`；生产模式重新 `npm run build` 后 `npm start`。真实 iPhone Safari 的工具栏、返回手势和完整任务仍需用户验收，不能用 Chrome 手机视口替代。
